class Value:
    """ stores a single scalar value and its gradient """

    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0
        # internal variables used for autograd graph construction
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op # the op that produced this node, for graphviz / debugging / etc

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward

        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward

        return out

    def __pow__(self, other):
        assert isinstance(other, (int, float)), "only supporting int/float powers for now"
        out = Value(self.data**other, (self,), f'**{other}')

        def _backward():
            self.grad += (other * self.data**(other-1)) * out.grad
        out._backward = _backward

        return out

    def relu(self):
        out = Value(0 if self.data < 0 else self.data, (self,), 'ReLU')

        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward

        return out

    def backward(self):

        # topological order all of the children in the graph
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        # go one variable at a time and apply the chain rule to get its gradient
        self.grad = 1
        for v in reversed(topo):
            v._backward()

    def __neg__(self): # -self
        return self * -1

    def __radd__(self, other): # other + self
        return self + other

    def __sub__(self, other): # self - other
        return self + (-other)

    def __rsub__(self, other): # other - self
        return other + (-self)

    def __rmul__(self, other): # other * self
        return self * other

    def __truediv__(self, other): # self / other
        return self * other**-1

    def __rtruediv__(self, other): # other / self
        return other * self**-1

    def __repr__(self):
        return f"Value(data={self.data}, grad={self.grad})"

## F02

When Value.backward() is called, where does traversal begin, how is the topological list constructed, what gradient is seeded, and in what direction are the stored backward functions executed?

Answerable: True

### Generated answer

When you call `Value.backward()`, the algorithm starts the traversal at the node on which you invoked the method (the output node, `self`).  
It builds a topological ordering of all nodes reachable from that output by a depth‑first recursion: each node is added to a list **after** all of its children have been visited (`topo.append(v)` inside `build_topo`). This yields a post‑order list of the graph.  
Before the backward pass it seeds the gradient of the output node with `1` (`self.grad = 1`).  
Finally, it walks the list in reverse order (`for v in reversed(topo):`) and calls each node’s stored `_backward` closure, thereby executing the backward functions from the output back toward the leaves. (Source 1)

## F03

For x = Value(3.0) and y = x + x, what should x.grad be after y.backward(), and which implementation details produce that result?

Answerable: True

### Generated answer

`x.grad` will be **2** after calling `y.backward()`.

The reason is the way `Value.__add__` and `Value.backward` are implemented:

* `__add__` creates a new `Value` node whose `_prev` set contains the two operands and defines a `_backward` function that adds the output’s gradient to **both** operands’ `grad` fields:

```python
def __add__(self, other):
    ...
    out = Value(self.data + other.data, (self, other), '+')
    def _backward():
        self.grad += out.grad
        other.grad += out.grad
    out._backward = _backward
    return out
```
(Source 1)

* `backward()` first sets the gradient of the final node (`y`) to 1 and then, in reverse topological order, calls each node’s `_backward` function. When `y`’s `_backward` runs, it adds `out.grad` (which is 1) to `self.grad` **twice**—once for `self` and once for `other`. Since `x` is both operands (`x + x`), the two additions accumulate, giving `x.grad = 1 + 1 = 2`. (Source 1)

### Expected claims

- x.grad should be 2.
- The output gradient is seeded to 1.
- Both operands of the addition refer to the same x object.
- The addition backward function accumulates the output gradient into both operand references using +=.

## F04

How does Value.relu() behave in both the forward and backward passes for negative, exactly zero, and positive inputs?

Answerable: True

### Generated answer

`Value.relu()` creates a new `Value` whose data is the ReLU of the input:

* **Forward pass** – the output data is `0` if the input’s `data` is **negative**; otherwise it is the input’s data unchanged. Since the test uses `self.data < 0`, an input of exactly `0` falls into the “else” branch and also yields `0` (so both negative and zero inputs produce `0`, positive inputs pass through unchanged) (Source 4).

* **Backward pass** – the gradient w.r.t. the input is multiplied by the Boolean `(out.data > 0)`. Because `out.data` is the forward‑pass result, the gradient is propagated **only when the output is strictly positive**. For a negative input (output = 0) the condition is false → gradient = 0. For an input of exactly zero the output is also 0, so the condition is false → gradient = 0. For a positive input the output is positive, the condition is true → the upstream gradient is passed unchanged to the input (Source 4).

### Expected claims

- A negative input produces forward output 0.
- An input of exactly zero produces forward output 0.
- A positive input is passed through unchanged.
- The backward contribution is zero for negative and exactly zero outputs.
- For a positive output, the incoming output gradient is accumulated into the input gradient.

class Neuron(Module):

    def __init__(self, nin, nonlin=True):
        self.w = [Value(random.uniform(-1,1)) for _ in range(nin)]
        self.b = Value(0)
        self.nonlin = nonlin

    def __call__(self, x):
        act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
        return act.relu() if self.nonlin else act

    def parameters(self):
        return self.w + [self.b]

    def __repr__(self):
        return f"{'ReLU' if self.nonlin else 'Linear'}Neuron({len(self.w)})"

class Value:
    """ stores a single scalar value and its gradient """

    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0
        # internal variables used for autograd graph construction
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op # the op that produced this node, for graphviz / debugging / etc

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward

        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward

        return out

    def __pow__(self, other):
        assert isinstance(other, (int, float)), "only supporting int/float powers for now"
        out = Value(self.data**other, (self,), f'**{other}')

        def _backward():
            self.grad += (other * self.data**(other-1)) * out.grad
        out._backward = _backward

        return out

    def relu(self):
        out = Value(0 if self.data < 0 else self.data, (self,), 'ReLU')

        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward

        return out

    def backward(self):

        # topological order all of the children in the graph
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        # go one variable at a time and apply the chain rule to get its gradient
        self.grad = 1
        for v in reversed(topo):
            v._backward()

    def __neg__(self): # -self
        return self * -1

    def __radd__(self, other): # other + self
        return self + other

    def __sub__(self, other): # self - other
        return self + (-other)

    def __rsub__(self, other): # other - self
        return other + (-self)

    def __rmul__(self, other): # other * self
        return self * other

    def __truediv__(self, other): # self / other
        return self * other**-1

    def __rtruediv__(self, other): # other / self
        return other * self**-1

    def __repr__(self):
        return f"Value(data={self.data}, grad={self.grad})"

## F06

How does MLP construct and execute its layers, and why is its final layer linear rather than ReLU?

Answerable: True

### Generated answer

The **MLP** builds its network in two steps:

1. **Construction of the layers** – In `MLP.__init__` it creates a list of `Layer` objects, one for each entry in the `nouts` list.  
   ```python
   self.layers = [Layer(sz[i], sz[i+1],
                       nonlin=i!=len(nouts)-1)   # ← non‑linear unless it’s the last layer
                for i in range(len(nouts))]
   ```  
   (Source 1). The `nonlin` flag is set to `True` for every layer except the one whose index `i` equals `len(nouts)-1`, i.e., the final layer.

2. **Execution of the layers** – The `__call__` method simply feeds the input through each layer in order:
   ```python
   for layer in self.layers:
       x = layer(x)
   return x
   ```  
   (Source 1). Each `Layer` in turn calls all of its `Neuron`s (Source 2), and each `Neuron` applies either a ReLU activation or a plain linear combination depending on its `nonlin` flag (Source 3).

**Why the final layer is linear:**  
When a `Layer` is created for the last index, `nonlin` is set to `False` (`i != len(nouts)-1` is `False`). Consequently each `Neuron` in that layer is instantiated with `nonlin=False`, causing its `__call__` to return the raw affine sum `act` instead of `act.relu()` (Source 3). Therefore the MLP’s last layer performs only a linear transformation, while all preceding layers use ReLU.

- It creates a Layer between every consecutive pair of sizes.
- All layers except the last are constructed with nonlinearity enabled.
- The last layer is constructed with nonlinearity disabled.
- The input is passed through the layers sequentially.

### Generated answer

The MLP constructor builds a list of Layer objects, and each Layer creates a list of Neuron objects.  

* **MLP parameters** – `MLP.parameters()` walks through every layer and returns the concatenation of each layer’s parameters (Source 1).  
* **Layer parameters** – `Layer.parameters()` returns the parameters of each neuron in the layer (Source 2).  
* **Neuron parameters** – each Neuron stores a weight `self.w` list of length *nin* and a bias `self.b`; its `parameters()` method returns all those Value objects (Source 3).

For `MLP(3, [4, 4, 1])` the architecture is:

| Layer | nin | nout | Params per neuron = nin + 1 (bias) | Total params in layer |
|-------|-----|------|-----------------------------------|------------------------|
| 0 (hidden) | 3 | 4 | 3 + 1 = 4 | 4 neurons × 4 = **16** |
| 1 (hidden) | 4 | 4 | 4 + 1 = 5 | 4 neurons × 5 = **20** |
| 2 (output) | 4 | 1 | 4 + 1 = 5 | 1 neuron × 5 = **5** |

**Total trainable Value parameters:** 16 + 20 + 5 = **41**.

Thus, the MLP contains 16 parameters in the first layer, 20 in the second layer, 5 in the final layer, for a total of 41 trainable Value objects, collected by the nested `parameters()` calls described above. (Sources 1‑3)

The engine tests create a **reference implementation with PyTorch**: each test builds the same computation graph twice – once with `micrograd.Value` objects and once with `torch.Tensor`s that have `requires_grad=True`. | Test | Forward‑value check | Gradient check |
|------|---------------------|----------------|
| **`test_sanity_check`** | Uses exact equality: `assert ymg.data == ypt.data.item()` | Uses exact equality: `assert xmg.grad == xpt.grad.item()` |

class Value:
    """ stores a single scalar value and its gradient """

    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0
        # internal variables used for autograd graph construction
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op # the op that produced this node, for graphviz / debugging / etc

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward

        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward

        return out

    def __pow__(self, other):
        assert isinstance(other, (int, float)), "only supporting int/float powers for now"
        out = Value(self.data**other, (self,), f'**{other}')

        def _backward():
            self.grad += (other * self.data**(other-1)) * out.grad
        out._backward = _backward

        return out

    def relu(self):
        out = Value(0 if self.data < 0 else self.data, (self,), 'ReLU')

        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward

        return out

    def backward(self):

        # topological order all of the children in the graph
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        # go one variable at a time and apply the chain rule to get its gradient
        self.grad = 1
        for v in reversed(topo):
            v._backward()

    def __neg__(self): # -self
        return self * -1

    def __radd__(self, other): # other + self
        return self + other

    def __sub__(self, other): # self - other
        return self + (-other)

    def __rsub__(self, other): # other - self
        return other + (-self)

    def __rmul__(self, other): # other * self
        return self * other

    def __truediv__(self, other): # self / other
        return self * other**-1

    def __rtruediv__(self, other): # other / self
        return other * self**-1

    def __repr__(self):
        return f"Value(data={self.data}, grad={self.grad})"

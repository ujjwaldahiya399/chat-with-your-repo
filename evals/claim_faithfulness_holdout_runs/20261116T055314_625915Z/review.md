a = Value(-4.0)
b = Value(2.0)

class Value:
    """ stores a single scalar value and its gradient """

    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0
        # internal variables used for autograd graph construction
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op # the op that produced this node, for graphviz / debugging / etc

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward

        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward

        return out

    def __pow__(self, other):
        assert isinstance(other, (int, float)), "only supporting int/float powers for now"
        out = Value(self.data**other, (self,), f'**{other}')

        def _backward():
            self.grad += (other * self.data**(other-1)) * out.grad
        out._backward = _backward

        return out

    def relu(self):
        out = Value(0 if self.data < 0 else self.data, (self,), 'ReLU')

        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward

        return out

    def backward(self):

        # topological order all of the children in the graph
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        # go one variable at a time and apply the chain rule to get its gradient
        self.grad = 1
        for v in reversed(topo):
            v._backward()

    def __neg__(self): # -self
        return self * -1

    def __radd__(self, other): # other + self
        return self + other

    def __sub__(self, other): # self - other
        return self + (-other)

    def __rsub__(self, other): # other - self
        return other + (-self)

    def __rmul__(self, other): # other * self
        return self * other

    def __truediv__(self, other): # self / other
        return self * other**-1

    def __rtruediv__(self, other): # other / self
        return other * self**-1

    def __repr__(self):
        return f"Value(data={self.data}, grad={self.grad})"

## H02

How does Neuron compute an activation when its input list contains ordinary Python numbers, and which Value operations keep the weighted sum differentiable?

Answerable: True

### Generated answer

`Neuron.__call__` builds the activation by multiplying each weight (a `Value`) with the corresponding input element and then adding all those products together with the bias `Value` `self.b`:

```python
act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
```

Because `wi` is a `Value`, the `*` operator is the `Value.__mul__` overload, which works even when `xi` is an ordinary Python number, producing another `Value` that records the multiplication in the computational graph. The built‑in `sum` starts from the bias `Value` and uses `Value.__add__` to combine the terms, so the whole weighted sum remains a `Value`. Finally, if the neuron is non‑linear, `act.relu()` is called, which is the `Value.relu` method that returns a new `Value` representing the ReLU of the sum. All of these operations (multiplication, addition, and ReLU) are defined on `Value` and therefore keep the weighted sum differentiable. (Source 1)

- Neuron pairs weights and inputs with zip.
- Each paired weight and input are multiplied.
- Value.__mul__ converts a non-Value operand into a Value.
- Python sum starts the accumulated activation from the neuron's bias.
- Value.__add__ creates graph nodes and its backward closure accumulates gradients into both operands.
- The activation is passed through ReLU only when the neuron's nonlin flag is true.

class Neuron(Module):

    def __init__(self, nin, nonlin=True):
        self.w = [Value(random.uniform(-1,1)) for _ in range(nin)]
        self.b = Value(0)
        self.nonlin = nonlin

    def __call__(self, x):
        act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
        return act.relu() if self.nonlin else act

    def parameters(self):
        return self.w + [self.b]

    def __repr__(self):
        return f"{'ReLU' if self.nonlin else 'Linear'}Neuron({len(self.w)})"

## H03

What happens if Neuron(3) is called with only two inputs or with four inputs? Explain the behavior from the implementation and state whether an input-length check is performed.

Answerable: True

### Generated answer

`Neuron.__call__` computes the activation with  

```python
act = sum((wi*xi for wi, xi in zip(self.w, x)), self.b)
```  

`zip(self.w, x)` pairs each weight with an input **only up to the length of the shorter sequence**. Therefore:

* If a `Neuron(3)` (which creates three weight `Value`s) is called with **only two inputs**, the `zip` will iterate over the first two weight‑input pairs; the third weight is simply ignored.  
* If it is called with **four inputs**, `zip` will stop after the first three pairs, discarding the extra fourth input.

In both cases the code does **not raise an error** or perform any explicit length validation; it silently truncates (or ignores) mismatched inputs. No input‑length check is implemented in the `Neuron` class. (Source 2)

### Expected claims

- The implementation uses zip to pair weights and inputs.
- With two inputs, only two of the three weights participate.
- With four inputs, the fourth input is ignored.
- The bias is still included in the activation.
- Neuron.__call__ performs no explicit input-length validation.

## H04

What does Layer.__call__ return for one neuron versus multiple neurons, and how does that affect the intermediate and final values produced by MLP(2, [3, 1])?

Answerable: True

### Generated answer

`Layer.__call__` builds a list of the activations of all its neurons:

```python
out = [n(x) for n in self.neurons]
return out[0] if len(out) == 1 else out
```

- **When the layer contains a single neuron** (`len(out) == 1`), it returns the **scalar activation** of that neuron (`out[0]`), not a list.  
- **When the layer contains multiple neurons**, it returns the **list of activations** (`out`).

In an `MLP(2, [3, 1])` the network is constructed with two layers:

1. **First layer** – `Layer(2, 3, nonlin=True)` has **three neurons**, so its `__call__` returns a **list of three `Value` objects** (the intermediate outputs of the hidden layer).  
2. **Second layer** – `Layer(3, 1, nonlin=False)` has **one neuron**, so its `__call__` returns a **single `Value` object** (the final output of the network).

Thus, when the `MLP` is invoked, the first layer produces a list of three intermediate values, which is then passed as the input list to the second layer. The second layer collapses that list to a single scalar `Value`, which becomes the MLP’s final output. (Source 2, Source 1)

### Expected claims

- A one-neuron Layer returns its sole output directly rather than a list.
- A Layer with multiple neurons returns a list of outputs.
- The first layer of MLP(2, [3, 1]) produces a three-element list.
- The final one-neuron layer produces a single Value.
- MLP passes each layer's output directly into the next layer.

## H06

For x = Value(2.0) and y = x * 3, what is x.grad after calling y.backward() once and then a second time without clearing gradients? Explain why and identify the network helper that can clear parameter gradients.

Answerable: True

### Generated answer

When you build  

```python
x = Value(2.0)
y = x * 3
```  

the multiplication creates a new `Value` node whose backward function does  

```python
self.grad += other.data * out.grad   # adds 3·out.grad to x.grad
other.grad += self.data * out.grad   # adds 2·out.grad to the constant 3
```  

Calling `y.backward()` sets `y.grad = 1` and then runs the stored `_backward` functions. The first call therefore adds `3 × 1 = 3` to `x.grad`, so after the first backward **`x.grad == 3`**.

If you call `y.backward()` a second time **without clearing gradients**, the same backward logic runs again, adding another 3 to the existing gradient. The `backward` method does **not** reset `x.grad` (or any other node’s grad) before accumulating, so after the second call **`x.grad == 6`**.

The reason is that gradients are accumulated across backward passes; you must explicitly zero them out if you want a fresh gradient computation.

The network helper that clears parameter gradients is the `zero_grad` method defined in `micrograd/nn.py`’s `Module` class, which sets each parameter’s `grad` back to 0【Source 4】.  

(Behaviour of `backward` and gradient accumulation is shown in the `Value` class implementation【Source 1】.)

### Expected claims

- After the first backward call, x.grad is 3.
- After the second backward call without clearing, x.grad is 6.
- backward sets the output y.grad to 1 on each call.
- backward does not clear the existing gradient on x.
- The multiplication closure accumulates 3 times the output gradient into x.grad.
- Module.zero_grad clears gradients for parameters returned by a network module.

class Neuron(Module):

    def __init__(self, nin, nonlin=True):
        self.w = [Value(random.uniform(-1,1)) for _ in range(nin)]
        self.b = Value(0)
        self.nonlin = nonlin

    def __call__(self, x):
        act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
        return act.relu() if self.nonlin else act

    def parameters(self):
        return self.w + [self.b]

    def __repr__(self):
        return f"{'ReLU' if self.nonlin else 'Linear'}Neuron({len(self.w)})"

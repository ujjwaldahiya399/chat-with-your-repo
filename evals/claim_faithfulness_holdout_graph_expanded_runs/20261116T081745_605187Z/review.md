![awww](puppy.jpg)

A tiny Autograd engine (with a bite! :)). Implements backpropagation (reverse-mode autodiff) over a dynamically built DAG and a small neural networks library on top of it with a PyTorch-like API. class Value:
    """ stores a single scalar value and its gradient """

    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0
        # internal variables used for autograd graph construction
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op # the op that produced this node, for graphviz / debugging / etc

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward

        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward

        return out

    def __pow__(self, other):
        assert isinstance(other, (int, float)), "only supporting int/float powers for now"
        out = Value(self.data**other, (self,), f'**{other}')

        def _backward():
            self.grad += (other * self.data**(other-1)) * out.grad
        out._backward = _backward

        return out

    def relu(self):
        out = Value(0 if self.data < 0 else self.data, (self,), 'ReLU')

        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward

        return out

    def backward(self):

        # topological order all of the children in the graph
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        # go one variable at a time and apply the chain rule to get its gradient
        self.grad = 1
        for v in reversed(topo):
            v._backward()

    def __neg__(self): # -self
        return self * -1

    def __radd__(self, other): # other + self
        return self + other

    def __sub__(self, other): # self - other
        return self + (-other)

    def __rsub__(self, other): # other - self
        return other + (-self)

    def __rmul__(self, other): # other * self
        return self * other

    def __truediv__(self, other): # self / other
        return self * other**-1

    def __rtruediv__(self, other): # other / self
        return other * self**-1

    def __repr__(self):
        return f"Value(data={self.data}, grad={self.grad})"

## H02

How does Neuron compute an activation when its input list contains ordinary Python numbers, and which Value operations keep the weighted sum differentiable?

Answerable: True

### Generated answer

The `Neuron` multiplies each weight (a `Value`) by the corresponding input element with the `*` operator and adds the results together, starting from the bias `self.b` (also a `Value`).  
When an element of the input list `x` is an ordinary Python number, the `Value.__mul__` implementation first wraps that number in a `Value` object before doing the multiplication, so the product `wi*xi` is itself a `Value`. The built‑in `sum` then adds those products together using `Value.__add__`, which also returns a `Value`. Consequently the whole weighted sum `act` remains a `Value` and stays part of the autograd graph. Finally, if the neuron is non‑linear it calls `act.relu()`, which creates another `Value` (with a ReLU operation) that also defines a backward method, keeping the computation differentiable.  

Thus the activation is computed by `Value`‑based multiplication, addition, and (optionally) the `relu` method, all of which preserve differentiability.  

Citations: Neuron’s `__call__` uses multiplication and addition of `Value`s (Source 1); the `Value` class defines `__mul__`, `__add__`, and `relu` that wrap scalars and maintain gradients (Source 3).

### Expected claims

- Neuron pairs weights and inputs with zip.
- Each paired weight and input are multiplied.
- Value.__mul__ converts a non-Value operand into a Value.
- Python sum starts the accumulated activation from the neuron's bias.
- Value.__add__ creates graph nodes and its backward closure accumulates gradients into both operands.
- The activation is passed through ReLU only when the neuron's nonlin flag is true.

class Neuron(Module):

    def __init__(self, nin, nonlin=True):
        self.w = [Value(random.uniform(-1,1)) for _ in range(nin)]

## H03

What happens if Neuron(3) is called with only two inputs or with four inputs? Explain the behavior from the implementation and state whether an input-length check is performed.

Answerable: True

### Generated answer

`Neuron.__call__` simply zips the neuron’s weight list `self.w` with the supplied input list `x` and sums the products plus the bias:

```python
act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
```

`zip` stops at the shorter of the two sequences, so the method **does not verify** that the number of inputs matches the number of weights.  

* If the neuron is called with **fewer inputs than weights** (e.g., `Neuron(3)` but only two inputs), the extra weight(s) are ignored and the activation is computed using only the available input‑weight pairs plus the bias.  
* If it is called with **more inputs than weights** (e.g., four inputs), the surplus inputs are ignored for the same reason—`zip` only yields pairs up to the length of `self.w`.  

Thus, no explicit input‑length check is performed; the implementation silently truncates or ignores mismatched inputs. (Source 3)

### Expected claims

- The implementation uses zip to pair weights and inputs.
- With two inputs, only two of the three weights participate.
- With four inputs, the fourth input is ignored.
- The bias is still included in the activation.
- Neuron.__call__ performs no explicit input-length validation.

## H04

What does Layer.__call__ return for one neuron versus multiple neurons, and how does that affect the intermediate and final values produced by MLP(2, [3, 1])?

Answerable: True

### Generated answer

`Layer.__call__` builds a list **out** of the results of each neuron in the layer and then returns  

* the sole element `out[0]` when the layer contains **exactly one neuron**,  
* the full list `out` when the layer contains **more than one neuron**.  

This logic is shown in the implementation:

```python
def __call__(self, x):
    out = [n(x) for n in self.neurons]
    return out[0] if len(out) == 1 else out      # (Source 3)
```

When an `MLP` is created as `MLP(2, [3, 1])` (two inputs, a hidden layer of 3 neurons followed by an output layer of 1 neuron), the `MLP.__call__` method iterates through its two `Layer` objects (Source 1):

```python
def __call__(self, x):
    for layer in self.layers:
        x = layer(x)
    return x
```

* **First layer (3 neurons)** – `len(out) == 3`, so the layer returns a **list of three `Value` objects**. This list becomes the input `x` for the next layer.
* **Second layer (1 neuron)** – `len(out) == 1`, so the layer returns **the single `Value` object** `out[0]`. This single `Value` is the final result of the MLP.

Thus, the intermediate representation after the hidden layer is a list of three activations, while the final output of `MLP(2, [3, 1])` is a single `Value` scalar.

### Expected claims

- A one-neuron Layer returns its sole output directly rather than a list.
- A Layer with multiple neurons returns a list of outputs.
- The first layer of MLP(2, [3, 1]) produces a three-element list.
- The final one-neuron layer produces a single Value.
- MLP passes each layer's output directly into the next layer.

## H06

For x = Value(2.0) and y = x * 3, what is x.grad after calling y.backward() once and then a second time without clearing gradients? Explain why and identify the network helper that can clear parameter gradients.

Answerable: True

### Generated answer

When you create  

```python
x = Value(2.0)
y = x * 3
```  

the multiplication node stores the two children — `x` and a `Value(3)`.  
During `y.backward()` the `backward` method first sets the output’s gradient to 1 and then runs the saved `_backward` function of the `*` operator, which adds to each child’s gradient:

* `self.grad += other.data * out.grad` → `x.grad += 3 * 1` (Source 1)  

So after the **first** call, `x.grad == 3`.

If you call `y.backward()` **again** without resetting gradients, the same process runs a second time. The output gradient is again set to 1, and the `_backward` function adds another `3` to `x.grad`. Because `x.grad` was **not cleared**, it accumulates:

* after second call: `x.grad = 3 (previous) + 3 = 6`.

Thus the gradient doubles each time you invoke `backward` on the same graph unless you zero it first.

The helper that can clear (reset) the stored gradients for all parameters is the `zero_grad` method of the `Module` class, which iterates over the parameters and sets their `grad` fields to 0 (Source 4). This method is typically called before a new backward pass in training loops.

### Expected claims

- After the first backward call, x.grad is 3.
- After the second backward call without clearing, x.grad is 6.
- backward sets the output y.grad to 1 on each call.
- backward does not clear the existing gradient on x.
- The multiplication closure accumulates 3 times the output gradient into x.grad.
- Module.zero_grad clears gradients for parameters returned by a network module.

How does Value.__pow__ treat x ** 2 compared with x ** Value(2), which node is stored as a predecessor, and for which operand does its backward closure calculate a gradient?

class Value:
    """ stores a single scalar value and its gradient """

    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0
        # internal variables used for autograd graph construction
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op # the op that produced this node, for graphviz / debugging / etc

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward

        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward

        return out

    def __pow__(self, other):
        assert isinstance(other, (int, float)), "only supporting int/float powers for now"
        out = Value(self.data**other, (self,), f'**{other}')

        def _backward():
            self.grad += (other * self.data**(other-1)) * out.grad
        out._backward = _backward

        return out

    def relu(self):
        out = Value(0 if self.data < 0 else self.data, (self,), 'ReLU')

        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward

        return out

    def backward(self):

        # topological order all of the children in the graph
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        # go one variable at a time and apply the chain rule to get its gradient
        self.grad = 1
        for v in reversed(topo):
            v._backward()

    def __neg__(self): # -self
        return self * -1

    def __radd__(self, other): # other + self
        return self + other

    def __sub__(self, other): # self - other
        return self + (-other)

    def __rsub__(self, other): # other - self
        return other + (-self)

    def __rmul__(self, other): # other * self
        return self * other

    def __truediv__(self, other): # self / other
        return self * other**-1

    def __rtruediv__(self, other): # other / self
        return other * self**-1

    def __repr__(self):
        return f"Value(data={self.data}, grad={self.grad})"

class MLP(Module):

    def __init__(self, nin, nouts):
        sz = [nin] + nouts
        self.layers = [Layer(sz[i], sz[i+1], nonlin=i!=len(nouts)-1) for i in range(len(nouts))]

        return x

    def parameters(self):
        return [p for layer in self.layers for p in layer.parameters()]

# micrograd

![awww](puppy.jpg)

A tiny Autograd engine (with a bite! :)). Implements backpropagation (reverse-mode autodiff) over a dynamically built DAG and a small neural networks library on top of it with a PyTorch-like API. Both are tiny, with about 100 and 50 lines of code respectively. The DAG only operates over scalar values, so e.g. we chop up each neuron into all of its individual tiny adds and multiplies. However, this is enough to build up entire deep neural nets doing binary classification, as the demo notebook shows. Potentially useful for educational purposes.

### Installation

```bash
pip install micrograd
```

### Example usage

Below is a slightly contrived example showing a number of possible supported operations:

```python
from micrograd.engine import Value

a = Value(-4.0)
b = Value(2.0)
c = a + b
d = a * b + b**3
c += c + 1
c += 1 + c + (-a)
d += d * 2 + (b + a).relu()
d += 3 * d + (b - a).relu()
e = c - d
f = e**2
g = f / 2.0
g += 10.0 / f
print(f'{g.data:.4f}') # prints 24.7041, the outcome of this forward pass
g.backward()
print(f'{a.grad:.4f}') # prints 138.8338, i.e. the numerical value of dg/da
print(f'{b.grad:.4f}') # prints 645.5773, i.e. the numerical value of dg/db
```

### Training a neural net

The notebook `demo.ipynb` provides a full demo of training an 2-layer neural network (MLP) binary classifier. This is achieved by initializing a neural net from `micrograd.nn` module, implementing a simple svm "max-margin" binary classification loss and using SGD for optimization. As shown in the notebook, using a 2-layer neural net with two 16-node hidden layers we achieve the following decision boundary on the moon dataset:

![2d neuron](moon_mlp.png)

### Training a GPT

For a more advanced example, see [microgpt](https://gist.github.com/karpathy/8627fe009c40f57531cb18360106ce95), which trains and samples from a full GPT-2-like transformer in pure, dependency-free Python. It builds on a more efficient and better version of the autograd engine here (storing local gradients at forward time instead of per-op backward closures), and is the complete algorithm in a single file — everything else is just efficiency. See also the accompanying [explainer post](https://karpathy.github.io/2026/02/12/microgpt/) for a detailed walkthrough.
